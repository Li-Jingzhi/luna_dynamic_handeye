# 坐标与机型约定

所有4×4矩阵写为`目标←来源`，长度m、角度输入deg，旋转向量内部rad。

## 本次纠正

`head_eye_pro`对应Marvin_pro。此前引用其`1004.ini`的287/314mm去评价Luna模型不成立。新工程只从该项目复制数学方法。

Luna使用`head_2dof_capt/configs/luna_new.ini`：双臂264/264mm、首段158.6mm、固定FLANGE 87mm，右臂实测球偏移[0,0,101]mm。FK已包含87mm固定段，不可再加一次。左右臂的MDH数值相同不表示其父系重合。本版输出右臂R.A1 MDH父系。

Luna双目左CSI0、右CSI1，校正外参`right_from_left_T_m=[-0.0595383553,0,0]`，因此正深度的标准视差`uL-uR`为正。Marvin_pro那套正基线/负视差不能套用。所有原始JSON及哈希保留。

## 头部运动链

实机配套控制器表：

| 链序 | A mm | Alpha deg | D mm | Theta deg | 反馈 |
|---|---:|---:|---:|---:|---|
| 0 | 0 | 0 | 640 | 0 | head[0]，yaw |
| 1 | 0 | -90 | 0 | 0 | head[1]，pitch |

采用原采集FK约定`Rx(alpha) Tx(a) Rz(theta+q) Tz(d)`。640mm描述的是头部MDH根系的名义几何，不应把该根系自动当成MJCF躯干系；A负责连接头根与臂MDH父系。

LunaUdpTool MJCF：

`S=Gento Luna_Leg_J6_Link → Head_J1_Link → Head_J2_Link`。

`S←H(q)=F1 Rz(q1) F2 Rz(q2)`，F1约平移[-13.496,0,498.98]mm及Rx(+90°)，F2约Rx(-90°)。零位时第一轴指向S的-Y、第二轴指向S的+Z；假定S的Z竖直，是pitch→yaw。串联旋转顺序不交换，所以仅交换反馈索引还不能证明模型与实机等价。

模型给出的右臂[0,-214.6,391.5]mm、左臂[0,+214.6,391.5]mm、头末端零位[-13.496,0,498.98]mm，**全部相对于S**。这些不是地面基座位置，不是MDH父系位置，也不是镜头光心位置。

按用户确认，**控制器MDH为唯一运动学依据**。MJCF仅保留作结构参考，标定与推理入口均拒绝MJCF头链；不再通过反馈索引/符号映射启用替代头链。

## 标定外参与光学系

主模型为`M←C_rect = A K(q) B`。

B直接连接校正左眼与头末端，已包含光学轴定义与双目校正旋转。原始左眼与校正左眼满足`C_raw←C_rect=R1.T`；因此若导出原始光学安装，应使用`H←C_raw = B · R1`。不要在校正像素推理时再重复乘R1。

相机原始K/D描述2560×1984图像，校正后K对应1280×992。`Assets.triangulate(..., pixel_domain='raw')`接受原生2560×1984像素并用原始K/D、R1/R2和校正K转换；缩到1280×992但仍带畸变的中间图像不是这个raw接口的输入，应先按采集链处理。

## 参数唯一性与验收

同时估计两端6DoF安装与两个编码器零偏会出现两维规范自由度。本版固定零偏，估计12参数有效A/B，不解释为每个实体零件的独立精密测量。拟合使用Huber损失、Jacobian秩检查和归一化梯度收敛门控。

模型输出可连续随头角变化，但这只描述数学模型。正式推理还必须通过未见头姿、未见空间、新会话的独立验收。运动模式另需曝光和反馈时钟校验；当前真实数据仅支持停稳诊断。独立外部绝对精度还需外部计量。
