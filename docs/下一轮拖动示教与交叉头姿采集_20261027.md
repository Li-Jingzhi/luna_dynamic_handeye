# 下一轮拖动示教、回放与交叉头姿采集

本指南为较完整二维网格建议；当前用户已指定先采pitch=0的yaw扫描，本轮按[零俯仰专用指南](pitch0_yaw_capture.md)执行。

可以使用head_eye_pro的操作思路，但实际执行本工程的Luna采集代码。Pro最终pro_capture不采头角、相机契约及轨迹schema/MDH不同，不能直接在Luna上运行或混用其轨迹。本工程已有右臂拖动示教、固定头姿逆序回放、球位×头姿停稳交叉采集；尚未完整移植Pro的一键串联、左臂和部分轨迹恢复接口。

## 已有入口

|功能|入口|现状|
|---|---|---|
|拖动示教|acquisition/interactive_ball_calibration/capture.py teach|右臂，约每3°记录，至少18点；Ctrl+C结束并验证保存|
|固定头姿回放|同模块replay|按已教路径逆序回放，SDK速度/加速度5%，每点50唯一合格双目对|
|九头姿交叉采集|python -m dynamic_handeye capture|每个臂位依次采各头姿，机械臂不动，头停稳后采样；无--run仅离线检查|
|训练网格|configs/capture_plan.json|yaw=-10/0/+10 × pitch=-25/-20/-15，共9姿|
|独立验证网格|configs/capture_validation_plan.json|yaw=-5/0/+5 × pitch=-22.5/-17.5，共6姿；使用新轨迹/新会话|

以下只给出操作命令，本次没有连接设备。teach命令会连接控制器、必要时移动头部并进入拖动模式，不是离线预检。SDK与Orin相机服务须在现场按既有流程就绪，起始位置和路径由操作者核验；工程不会做环境碰撞规划。

## 操作顺序

在luna_dynamic_handeye根目录，先启动并核对Luna相机链，左右CSI0/CSI1、1280×992校正域和标定哈希一致。先读docs/acquisition.md的SDK/相机依赖说明。

### 1. 拖动示教新右臂轨迹

```bash
PYTHONPATH=acquisition .venv/bin/python -m interactive_ball_calibration.capture teach \
  --stereo configs/camera/luna_rectified_stereo.json \
  --mdh configs/robot/luna_new.ini --sdk-root ../00040701 \
  --latest acquisition/runtime/new_sh5_yellow/latest_pose.json \
  --head-target 0 -25 \
  --output datasets/raw/ball_taught_20261027_train.json
```

缓慢拖动，保持身体不动；轨迹覆盖近中远、左右/上下视场及不同法兰朝向，保证目标在拟采9头姿的公共可见区域。至少18个密集关节点；正式批次建议30–50个有效空间位置，同时保留连接路径，不能直接删掉连接点造成关节跳变。只固定法兰朝向平移，会削弱pF辨识。Ctrl+C完成验证并保存；不足18点会拒绝完成，不把partial文件当完整轨迹。

### 2. 固定头姿逆序回放，采集基准并回到轨迹首点

```bash
PYTHONPATH=acquisition .venv/bin/python -m interactive_ball_calibration.capture replay \
  --path datasets/raw/ball_taught_20261027_train.json \
  --stereo configs/camera/luna_rectified_stereo.json \
  --mdh configs/robot/luna_new.ini --sdk-root ../00040701 \
  --latest acquisition/runtime/new_sh5_yellow/latest_pose.json \
  --head-target 0 -25 \
  --output datasets/raw/ball_auto_20261027_train_reference.jsonl
```

保留终端RUN确认。示教通常结束在轨迹末端；交叉采集要求接近首点/续采点，不会从末端直接跳至首点。固定头姿逆序回放既补基准数据，也按已有路径回到首点附近。异常中断后不能假定已经到首点，应检查实际反馈再继续。

### 3. 九头姿预实验

先执行离线检查：

```bash
.venv/bin/python -m dynamic_handeye capture \
  --plan configs/capture_plan.json \
  --path datasets/raw/ball_taught_20261027_train.json \
  --output datasets/raw/ball_point_head_20261027_train.jsonl --stop-after 12
```

检查通过且现场就绪后，同一命令补上`--sdk-root ../00040701 --run`进入Luna实机流程，仍有终端RUN确认。12臂位×9头姿=108组合，若全有效则5400个双目对；这只是质量/可见性/链路预实验，不是精度验收。--stop-after按轨迹点数计数，不是自动选12个空间分散点。

预实验后扩大到同一路径前30–50点（不超过轨迹实际长度）。同文件续采必须保持计划、轨迹、相机/MDH/MJCF哈希绑定不变，机械臂处于期望续采点附近；保留capture_valid=false和拒绝原因，不按标定误差删点。

## 需要补采的数据与优先级

1. **交叉头姿是首要缺口。** 完整9姿网格尤其补[-10,-20]、[+10,-20]、[-10,-15]、[+10,-15]，每个臂位尽量采全9姿。目标是消除“所有非零yaw只在pitch=-25”的结构混淆，而不是继续堆积-25数据。
2. **返回重复性。** 在5–8个近中远/边缘固定臂位，做3–5轮参考姿→其他姿→参考姿的循环，比较回到[0,-25]时的漂移；正反接近方向分别记录。现有九姿适配器不会自动组织全部重复循环/方向标签，专项需单独安排，不能把同一窗口50帧当物理重复实验。
3. **独立未见头姿与新球位。** 模型、pF和补偿超参数冻结后，另示教新轨迹，在6个中间角度验证，建议15–20个新有效球位（示教轨迹本身仍至少18点，可采20点）。使用capture_validation_plan.json与独立输出，保留另一会话。不能用同一物理球位同时作训练和新球位验收。
4. **不同臂构型。** 增加不同法兰姿态及接近同一物理目标的不同臂构型，用于识别pF与FK构型偏差；不要用机械臂q7作为最终视觉推理输入。
5. **左臂与运动中测量后置。** 当前采集入口仅右臂；左臂需单独适配侧别和pF。先完成右臂停稳二维覆盖，再验证真实曝光时刻/共享时钟和运动模糊，不能把出队时间当曝光时间。

训练9姿与验证6姿均只覆盖yaw约±10、pitch[-25,-15]的局部域。若要任意机械限位内使用，应按可见性逐步扩展二维网格，不能凭本轮通过就推广到±90°全域。现有旧报告里的更宽角度计划是后续建议，不是本轮自动执行范围。

## 数据记录与后处理边界

保留逐帧校正像素/球心、q7和头角反馈、身体姿态、唯一帧号、时间字段、质量、来源哈希、轨迹/球位/头姿/会话标识及拒绝记录。现有源程序支持窗口元数据/反馈；本轮没有新增ROI/原始图像保存功能，若需排查检测偏差应另行补齐。记录实机为旧版Luna V2.0，日志未显式写版本时同时保留会话说明与计划。

每个组合仍采50个唯一合格双目对；满足帧数不等于达到1mm。下一步要同时评估重复性、完整头姿留出、新球位、臂构型及新会话误差。

当前`dynamic_handeye import`可校验新日志，但`dynamic_handeye fit`仍是固定名义头根的6参数入口；已保留的有效12参数＋躯干补偿研究脚本目前显式读取旧档案文件。新数据采好后须适配该研究拟合输入及验证划分，不能直接重跑旧脚本宣称新数据已标定。不要用通用fit命令混淆两种算法。

本次已验证teach/replay帮助入口及训练/验证计划离线检查；没有进行SDK连接、模式切换、相机重启或实机运动。
