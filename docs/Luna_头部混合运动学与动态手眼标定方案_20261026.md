# Luna 头部混合运动学与动态手眼标定方案

> 版本：v1.0 ｜ 日期：2026-10-26
> 适用项目：`luna_dynamic_handeye`
> 状态：**已确认控制器动作方向与关节限位；MJCF 提供名义安装几何；混合模型尚未部署和完成实机精度验收。**

## 1. 目标与最终约定

在双目安装于二自由度头部、双臂位置由各自控制器 MDH 正运动学（FK）给出的场景下，构造头姿相关的相机位姿

\[
{}^{S}T_{C}(q_h)
\]

将双目三角化的三维坐标从相机系转换到统一的躯干系 `S_MODEL`，再与左右臂 FK 进行比较、标定和验证。这里的目标是跨不同头姿保持视觉与 FK 坐标一致；**不能仅凭几何模型推导宣称已达到亚毫米精度**。

**已由实机动作确认：**

- `head[0]`：Yaw（偏航），绕竖直轴；从 `0°` 到 `-25°` 时 **右转**。
- `head[1]`：Pitch（俯仰），绕水平轴；从 `0°` 到 `-25°` 时 **低头**。
- 运动顺序采用控制器的 **Yaw → Pitch**，不直接采用 MJCF 原始的 **Pitch → Yaw**。
- 关节限位采用控制器：Yaw `[-90°, +90°]`，Pitch `[-25°, +25°]`。
- **固定安装几何采用 MJCF**：两个头部关节原点在 MJCF 零位重合；共同原点在 `S_MODEL` 中的名义位置为 `[-13.496, 0, 498.98] mm`。
- 实机控制器文件 `luna_new.ini` 的第一段头部 MDH `D=640 mm` **原样保留用于溯源**，不作为新混合模型中额外增加的平移。

### 坐标方向约定及待核实项

本方案采用右手系、列向量，**令新构造的头部零位参考系的 +X 表示机器人正前方，+Y 表示左侧，+Z 表示上方**。在该约定下，负 Yaw 表示右转；负 Pitch 表示低头。单轴实机动作已与该符号定义相符。

但 `S_MODEL` 是 MJCF 中 `Gento Luna_Leg_J6_Link` 的 **body 局部坐标系**，并非经独立核验的实机基座或固定世界坐标系。**实施前仍须核查 MJCF `S_MODEL` 的实际 +X/+Y/+Z 是否符合上述前、左、上约定。** 若不符，应引入一个**固定的、明确测定的轴向对齐旋转**，不能在未验证时把旋转式直接应用到实际 `S_MODEL`。下文主公式以二者轴向一致为前提。

## 3. 坐标系定义

- `S` / `S_MODEL`：MJCF `Gento Luna_Leg_J6_Link` body 原点；**不是地面世界坐标**。
- `H`：**新定义的头部公共旋转中心零位参考系**。原点取 MJCF 两头部关节的共同原点；轴向按本方案“前 X / 左 Y / 上 Z”定义。它不是 MJCF `Head_J1_Link` 的原有局部坐标轴，也不自动等于旧控制器 MDH 父系。
- `C`：经校正的左相机光学坐标系，需与三角化程序采用的像素域一致。
- `M_R`、`M_L`：右臂、左臂控制器 MDH 父系。
- `X = {}^{H(0,0)}T_C`：**零头姿下**从校正左相机坐标系到新头部参考系的固定 4×4 变换。其 6 个刚体自由度是后续标定对象；尽管写成零位安装关系，作为刚性安装参数在所有头姿下保持不变。

采用 `^{A}T_B` 表示把 B 系齐次坐标映射至 A 系，亦即 `P_A = ^A T_B P_B`。

### 名义固定头部中心

\[
{}^S p_H=\begin{bmatrix}-0.013496\\0\\0.49898\end{bmatrix}\ \mathrm{m}
\]

在 `H` 零位轴向与 `S` 对齐的条件下：

\[
{}^S T_H(0,0)=\operatorname{Trans}(-0.013496,0,0.49898).
\]

如果轴向核验表明 `S` 不等于前左上约定，令常量 `R_{S\leftarrow V}` 连接**前左上虚拟系 V**到 `S`，应使用经过轴向转换的完整旋转链，而不是直接套用下面的简化式。

## 4. 推荐的头部正运动学

令

\[
q_h=\begin{bmatrix}q_y\\q_p\end{bmatrix}
=\begin{bmatrix}\mathrm{head}[0]\\\mathrm{head}[1]\end{bmatrix},
\]

单位为角度（计算旋转矩阵前转换为 rad）。在**前左上零位轴向约定**下：

\[
\boxed{
{}^S T_C(q_h)=
\operatorname{Trans}(-0.013496,0,0.49898)
R_z(q_y)R_y(-q_p)X
}
\tag{1}
\]

上述每个 `R` 均按右手规则定义，并扩展为 4×4 齐次旋转矩阵。

**为什么 Pitch 要取负号？** 用户实机确认 `head[1] = -25°` 为低头。在 +X 正前方、+Z 向上的约定下，`R_y(+25°)` 会将朝前向量转为负 Z（向下）；故 `R_y(-q_p)` 与实机动作对应。

**为什么 Yaw 不取负号？** 用户实机确认 `head[0] = -25°` 为右转。在 +X 正前方、+Y 向左的约定下，`R_z(-25°)` 会将朝前向量转向负 Y（右侧）。

### 4.1 轴方向验证

设零位前向单位向量为 `f0 = [1,0,0]^T`：

- `q_y=-25°`, `q_p=0°`：`R_z(-25°) f0 ≈ [0.9063, -0.4226, 0]^T`，向右。
- `q_y=0°`, `q_p=-25°`：`R_y(+25°) f0 ≈ [0.9063, 0, -0.4226]^T`，向下。
- 两轴同时非零时，必须遵循 `R_z(q_y)R_y(-q_p)` 的顺序，不能交换旋转。

### 4.2 光心轨迹与姿态

令 `X = [R_X, t_X; 0,1]`，则

\[
{}^S R_C(q_h)=R_z(q_y)R_y(-q_p)R_X,
\]

\[
{}^S p_C(q_h)={}^S p_H+R_z(q_y)R_y(-q_p)t_X.
\]

因此，**两个关节中心重合不意味着转动时相机光心不动**。只要相机相对公共关节中心存在非零 `t_X`，其光心就会随头姿在空间移动。

## 5. 与原控制器 MDH 的关系及符号修正

原控制器头部表：

| 原始链 | A (mm) | Alpha (°) | D (mm) | Theta (°) | 关节 |
|---|---:|---:|---:|---:|---|
| `R.H.L0.DH` | 0 | 0 | **640** | 0 | Yaw |
| `R.H.L1.DH` | 0 | -90 | 0 | 0 | Pitch |

原项目采用

\[
T_i=R_x(\alpha_i)T_x(a_i)R_z(\theta_i+q_i)T_z(d_i).
\]

**不能在旧根系未知、旧表 `D=640` 保留的情况下，再额外叠加 MJCF 的 `498.98 mm`，否则几何关系重复或混乱。** 新模型选择把根系放在 MJCF 给出的共同关节中心，因而其 MDH *等价参数化* 可以取 `D0=D1=0`。

推荐实现优先采用式 (1)，无须 MDH。若为了兼容原 `mdh_poses` 函数，则可以选择下列**二者之一**：

**写法 A（推荐的重新参数化）**：输入 `[q_y, q_p]`，采用 `L0: α=0°, D=0; L1: α=+90°, D=0`，并在两段 MDH 后右乘固定的 `R_x(-90°)`，得到

\[
R_z(q_y)R_x(+90^\circ)R_z(q_p)R_x(-90^\circ)
=R_z(q_y)R_y(-q_p).
\]

**写法 B（保留旧 α 符号）**：输入 `[q_y, -q_p]`，采用 `L0: α=0°, D=0; L1: α=-90°, D=0`，并在两段 MDH 后右乘固定的 `R_x(+90°)`，得到同样的结果。

> **重要校正：** 旧表 `L1 α=-90°` 若直接传入 `q_p` 并在末端补 `R_x(+90°)`，得到的是 `R_y(+q_p)`，与已经确认的实机“负 Pitch 低头”约定不匹配。不能忽略这一符号差异。这里的附加固定旋转也可吸收到重新定义的零位相机外参中，但两者必须一致，不能重复计算。

上述等价式仅说明**新混合模型可以由 MDH 形式表示**，并非证明原控制器 `D=640` 的物理来源，也非要求修改控制器设备参数。

## 6. 六自由度相机外参标定

保持混合头部几何链固定，仅估计

\[
X={} ^{H(0,0)}T_C\in SE(3),
\]

即三维平移 + 三维旋转，共 6DoF。控制器角度应来自同一时间轴的真实反馈，而非仅使用指令值。

对每个样本 `i`：

1. 从双目同步或时间校正后的像素中三角化得到黄球球心 `p_{C,i}`，使用与 `X` 对应的**校正左相机坐标系**。
2. 读取对应曝光时刻的 `q_y,i` 和 `q_p,i`。
3. 根据机器人 FK 得到黄球中心在相应机械臂 MDH 父系中的位置 `p_{M,i}^{FK}`（如须使用法兰到球心的固定偏置 `p_F`，需保持同一套球心定义）。
4. 用 MJCF + 双臂 MDH 的名义安装变换将其转到统一的 `S_MODEL`：`p_{S,i}^{FK} = ^S T_{M} p_{M,i}^{FK}`。
5. 用式 (1) 计算 `p_{S,i}^{vision}(X)`，通过鲁棒非线性最小二乘拟合 `X`：

\[
\boxed{
\min_{X\in SE(3)}\sum_i\rho\left(
\left\|{}^S p_{i}^{\mathrm{vision}}(X)-{}^S p_{i}^{\mathrm{FK}}\right\|_2
\right)
}
\tag{2}
\]

拟合时不要再引入自由的头部根安装矩阵 `A`，否则会回到原十二参数模型并降低固定几何带来的约束价值。若独立验证表明真实安装与 MJCF 存在系统差异，再在有观测可辨识性的前提下引入小幅几何修正。

### 6.1 左右臂坐标转换

使用仓库的 `configs/robot/torso_mounts.json` 中的**完整 4×4** 名义安装矩阵：

\[
{}^{M_R}p_C=({}^S T_{M_R})^{-1}\,{}^S T_C(q_h)\,p_C,
\]

\[
{}^{M_L}p_C=({}^S T_{M_L})^{-1}\,{}^S T_C(q_h)\,p_C.
\]

其中齐次点最后一维为1；不能只减去三维安装平移，必须处理坐标轴旋转。双臂 nominal 原点分别约为 `[0,-56,391.501] mm`、`[0,+56,391.501] mm`（表达于 `S_MODEL` 中），两者均非第一关节原点，也非全局世界原点。

## 7. Python 参考实现

```python
import numpy as np

P_S_H_M = np.array([-0.013496, 0.0, 0.49898], dtype=float)


def rotz(theta):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([[c, -s, 0.0],
                     [s,  c, 0.0],
                     [0.0, 0.0, 1.0]])


def roty(theta):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([[ c, 0.0,  s],
                     [0.0, 1.0, 0.0],
                     [-s, 0.0,  c]])


def torso_from_camera(yaw_deg, pitch_deg, T_H_C):
    """混合模型；返回 ^S T_C，长度 m；T_H_C 为零头姿校正左眼外参。"""
    if not (-90.0 <= yaw_deg <= 90.0):
        raise ValueError("Yaw 超出控制器限位 [-90, 90] deg")
    if not (-25.0 <= pitch_deg <= 25.0):
        raise ValueError("Pitch 超出控制器限位 [-25, 25] deg")

    T_H_C = np.asarray(T_H_C, dtype=float)
    if T_H_C.shape != (4, 4) or not np.isfinite(T_H_C).all():
        raise ValueError("T_H_C 必须是有限的 4x4 矩阵")

    T_S_H = np.eye(4)
    T_S_H[:3, 3] = P_S_H_M

    R = rotz(np.deg2rad(yaw_deg)) @ roty(-np.deg2rad(pitch_deg))
    T_H_Hq = np.eye(4)
    T_H_Hq[:3, :3] = R

    return T_S_H @ T_H_Hq @ T_H_C


# 实际使用应传入经过标定的 T_H_C，不能将单位矩阵视为已标定相机外参。
# P_C_h = np.array([x, y, z, 1.0])
# P_S_h = torso_from_camera(yaw_deg, pitch_deg, T_H_C) @ P_C_h
```

工程实现建议**从源 MJCF 读取** `Head_J1_Link` 的 `pos`、第二关节零偏和固定 body 关系，避免手动改写后遗漏源模型版本；同时单独配置 **实机控制器→混合模型** 的关节顺序、符号、限位映射。上面代码只是主公式的直接、可独立验证实现。

## 8. 验证步骤及验收门槛

### 8.1 几何与符号验证（先做）

- [ ] 读取 MJCF 并验证 `S_MODEL` 的 X/Y/Z 实际方向，确认是否与“前左上”一致。
- [x] `head[0]: 0° → -25°`，实机向右转。
- [x] `head[1]: 0° → -25°`，实机向下低头。
- [ ] 验证 Yaw 的正角方向和 Pitch 的正角方向，以及 0° 反馈对应的物理零位。
- [ ] 验证 yaw 转动时的 Pitch 轴随 yaw 旋转，符合 Yaw→Pitch 串联顺序。
- [ ] 验证两个真实头部转轴是否相交，交点是否接近 MJCF 给出的名义坐标。
- [ ] 独立确认相机朝向、相机安装刚性、曝光时刻与关节反馈时刻。

### 8.2 数值与模型验证

- [ ] 单轴测试 `(-25°, 0°)`、`(0°, -25°)`、零位，对照实机可见动作和旋转矩阵。
- [ ] 复合角测试如 `(-25°, -15°)`，验证旋转顺序而不只是单轴符号。
- [ ] 与原十二参数诊断模型分别拟合、对照，但不混用新旧外参。
- [ ] 采用未见头姿、未见球位、不同采集会话进行分组验证；报告 XYZ 轴偏差、三维平均误差、RMS、P95、最大误差。
- [ ] 如目标为三维视觉–FK 偏差 P95 < 1 mm，以独立留出样本验证，不能将训练残差当验收结果。
- [ ] 头部连续运动时另做左右眼曝光时间、反馈插值、读出时间与运动模糊验证，不能用停稳模型合格替代动态验收。

**当前状态：** 上述混合模型仅为已约定的算法方案；仓库 `dynamic_handeye/geometry.py` 目前仍将 `controller_mdh` 视为唯一可执行头链，并显式拒绝其他 `chain`。应用前须开发独立的 `hybrid_mjcf_geometry` 模式、增加单元测试、重新标定 `X` 和进行独立实机验收。原控制器配置和原诊断模型均不应被覆盖。
